Known and retained: **A slug reads as historical after a rename.** `unit/command/track` survives `/track` being renamed and the `Anchor` moves instead. ### 2026-08-04 — A `SessionEnd` hook writes a cost log, and installs may write that one key
Context: The entry below rejected automatic emission on two grounds. It runs synchronously, not `async`: 0.68 s on a 1.3 MB transcript, and an async process risks being killed during teardown. It is idempotent by session id, because `SessionEnd` also fires on clear and resume, so one session can be reported more than once. The kit ships the hook in its own tracked `.claude/settings.json`, and `INSTALL.md` gains a **bounded** exception permitting installs to write it into a target: the `hooks.SessionEnd` key only, this hook only, proposed and signed off, refused outright if a `SessionEnd` hook already exists, skipped where `pwsh` is absent.

Amends: the entry below, whose rejection of automatic emission named the wrong hook event and treated the `settings.json` rule as fixed.
Known and retained: **"never write `settings.json`" is no longer absolute, so it is no longer checkable by inspection alone.** The exception is bounded in `INSTALL.md` to one key, one hook, and explicit sign-off, and says in terms that it does not generalise — but a bounded exception is still an exception, and the next proposal will argue from this precedent. ### 2026-08-04 — Cost is measured by a script, and the avoidable-work taxonomy is policy
Context: The proposal was that every workflow emit a closing block on completion — duration, tokens in and out, model, observations about its own waste, suggested optimisations, an estimated saving, and an "optimization debt" backlog item carrying frequency, estimated savings and confidence. A single copy under `~/.claude` was recommended and declined in favour of version control and portability. Not covered: Codex sessions store their transcripts elsewhere and are not measured. Per-command attribution runs from one command marker to the next, so a segment includes follow-up turns, approvals and corrections — it is not the isolated cost of a command, and the script says so.

### 2026-08-04 — `Measure-Session.ps1` is Claude Code only, and errors rather than reporting zero
Context: Asked whether the measurement works under Codex and Copilot. Chosen: Shape-check every transcript before summing it. `Get-TranscriptVendor` classifies by record shape, not by path, so an exported or relocated store is still judged correctly; the two discriminators were verified against every transcript on this machine (18 Claude, 4 Codex): no Claude record carries a top-level `payload`, no Codex record carries a top-level `message.usage`. Writing the tests surfaced two real bugs in the new code: `$detail` silently assigned to the `-Detail` switch parameter (PowerShell variable names are case-insensitive), and returning early from a `[System.IO.File]::ReadLines` enumerator leaked the file handle, breaking an unrelated test that rewrote the same fixture path.
Rejected: **A Codex reader now** — the mapping is exact and verified (`sum(last_token_usage) == total_token_usage` on both sampled sessions, and `total_tokens == input_tokens + output_tokens`, proving `cached_input_tokens` is a subset of `input_tokens` rather than additive), but `calls` would be per turn against Claude's per call, and `-Detail` has no `<command-name>` markers to segment on. ### 2026-08-08 — `/pr` absorbs the gate and thread phases; pull requests are never drafts
Context: The slice loop was four commands — `/slice` → `/pr` → `/verify` → `/resolve` — three of which run in the same session, on the same branch, with each one's output written into the previous one's artifact. That is one job invoked four times, and the hand-offs were the only thing the split bought. Separately, a draft pull request splits "opened" from "actually in review": reviewers and the CI gates that ignore drafts see nothing until someone remembers to mark it ready.
Chosen: `/pr` becomes the whole merge-ready pipeline in three ordered phases — description, gates, review threads — and owns the sequence only. `.claude/commands/verify.md` and `.claude/commands/resolve.md` keep sole ownership of their procedures, are run in full by `/pr`, and stay invocable standalone; nothing is copied between the files (*Single ownership*). Phase 3 runs automatically rather than waiting to be asked for: it queries threads immediately, and on an empty result gives the automated reviewers exactly one bounded wait via `tools/Wait-PullRequestCheck.ps1` before re-querying. Drafts are abolished — `/slice`, `/fix`, and `/pr` open a live pull request — and the *Git and delivery* carve-out widens from "opening a draft" to "opening a pull request", on the reversibility argument that closing an open PR is as cheap as closing an issue. Merging stays the user's.
Rejected: **Fold `/track` in too** — it runs after the merge in a fresh session, deliberately, so the session that wrote the code does not get to grade whether the slice is done; merging it would hand doneness to the party with an opinion about it. **Keep `/resolve` separate** — recommended at the time, on the grounds that waiting for review is a different order of wall-clock time from writing a description; overruled by the user, and answered instead by the bounded-wait rule above rather than by a poll loop. **Keep `/slice` and `/fix` opening drafts and have `/pr` ask before marking ready** — preserves the narrower carve-out untouched, but keeps the two-state problem that abolishing drafts exists to remove, and costs a confirmation per slice. **Restate the gate and thread rules inside `/pr`** — would make the command self-contained at the price of two copies of every rule, which this repository's contract forbids for exactly the reason that applies here.
Reversibility: cheap for the command structure; the widened authorization carve-out is a policy change and reverting it means re-adding an ask per pull request.
