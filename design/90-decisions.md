### 2026-08-19 — Design state becomes addressable records, and every restatement is either forbidden or checked
Context: `design/00-brief.md` (2026-08-19, previous entry) fixed the problem as repeated semantic reconstruction of current design state, and fenced ten non-goals around the answer. `/design` ran against it. The brief's constraints leave less room than they look: a fixed 16,384-byte per-unit ceiling against a corpus that only grows; readable by a human with a `git clone` and nothing else; multi-vendor, so nothing one tool can read and another cannot; no daemon, index, or cache; the 54-entry log append-only and unrestructured; GitHub authoritative for slice criteria *and* a no-network checkout still able to state the work and its order. `design/10-design.md` previously held the defect-to-merge path, whose slices S1-S3 all landed; it is rewritten in full per `.claude/commands/design.md`, and a pointer to `dfd1cab` retires the body the way `30-slices.md` retires a landed slice.
Chosen: Six entity kinds - **Unit** (the four kinds the tree already has: command, script, document, invariant), **Contract**, **Invariant**, **Decision**, **Question**, **WorkRef** - each a separately-openable text record, persisted, with no cache or index anywhere. Two commitments carry the whole design. **Current state is a fact with an address**: a session resolves a unit by name and reads its record, rather than deciding which parts of 216 KB are still true. **No generated prose is ever an input**: facts flow records-to-regions and never back, which is what gives the system the fixed point the reconstruction loop lacks, and is the property `Module boundaries` exists to protect. The governing rule is **every restatement is either forbidden or checked** - a record's tree anchor, a contract's declaration pointer, an invariant's evidence and a decision's log anchor are all restatements, permitted only because each resolution is mechanically verified, and every blocking divergence class is an instance of that one rule. The brief's ceiling is made checkable by defining **the orientation closure** as the unit's record plus one hop, excluding superseded decisions - one hop is the line between orienting and investigating, and archival exclusion is what makes a fixed ceiling survivable against an append-only log, since closure size then grows with a unit's *live* decisions and superseding one *shrinks* it. Decision extraction takes the standing claim and leaves the entry: **a log entry records what was decided on a date, a decision record records what is true now**, which is a fact and its history rather than two copies. The existing agent-fence rule generalises into the marked-region mechanism rather than being replaced, and reverse edges (which units an invariant binds, which units consume a contract) are derived and never written, surfacing only as projections. **A divergence class is blocking only if it can be evaluated from the checkout alone** - that single rule decides the closed list, and it is what keeps `gh` being unauthenticated from being reported as a divergence. A freeze downgrades blocking classes to reported and **exit 2 still stands**, because a freeze permits known staleness and not a checker that could not run. Two boundary conditions fall out of the kit's own shape: `tools/*.ps1` ships to targets and the kit's `design/` does not, so an absent state set is *could not evaluate*, never clean (the I8 shape); and every touched command degrades to today's behaviour without a state set, which is what makes the zero-hard-stops promise mechanical.
Rejected: **Grouping records into one document per unit kind** - seven files for a human offline instead of a few hundred, and the better answer on that criterion alone; rejected because the ceiling counts bytes a session loads, an agent handed a grouped document loads the document, and the metric would understate the real load while passing - the human-reading case is bought back by grouped *projections* instead. **JSON** - dependency-free and natively schema-validatable in PowerShell; rejected because it escapes every multi-line claim onto one line and fails the read-it-unaided criterion the brief states twice. **YAML** - reads well, carries block scalars; rejected because PowerShell Core ships no parser for it, putting an `Install-Module` between a checkout and its own design state. **Front matter inside each unit file** - zero drift between a unit and its record because they are the same file; rejected because the invariant and document units have no file to live in, it ships kit design state into eighteen targets, and it puts a 12 KB command file inside its own 16 KB budget. **A source digest stored in the region marker** - cheaper than regenerating, needs no generator at check time; rejected as a second copy of a fact that matches happily when both sides were edited together. **Convention alone, stated in `AGENTS.md` with nothing checking it** - rejected as the exact shape the 2026-08-10 entry records failing within a day, where a repin claimed as done had reached one issue of seventeen. **Pointers into the log with no extraction** - duplicates nothing and is the purest reading of *Single ownership*; rejected because resolving the pointer means opening the file the brief's first done criterion forbids opening. **Restructuring the log into records** - the only option with genuinely one copy, and a fenced non-goal. **Keeping the local slices document authoritative** - today's behaviour; rejected because the two-database duplication the brief measured survives it. **GitHub with no local mirror** - the cleanest single home; rejected because a checkout could then no longer say what the outstanding work is or in what order. **Everything mechanical blocks** - stricter and simpler to state; rejected because it fails a build for `gh` being unauthenticated, reporting an absent comparison as a divergence. **Report everything, block nothing** - collides with no freeze; rejected as a convention nothing checks, which is the failure the design answers. **Suppressing everything during a freeze** - the more literal reading of the done line; rejected because it makes writing `design/FROZEN.md` a way to switch the gate off, including for a broken checker.
Reversibility: **cheap as a document, expensive once records exist.** `design/10-design.md` is one file. The representation choice is not: once 49-plus records and their projections are written, changing granularity or format is a migration of the whole state set, and the one-way flow is the property that silently disappears if a later change lets a generated region be read back.
Known and retained: **A wrong claim in a record is not detected and cannot be.** Every mechanical property of the state set is checked; the truth of a standing claim is a behavioural assertion, which the brief's *no formal specification of behaviour* non-goal puts permanently out of scope. What the design buys is that a wrong claim is wrong in one addressable place rather than distributed across a corpus - a smaller promise than "the design cannot be wrong", and the honest one. **The design moves cost rather than only removing it**: a small structured write at every decision, in exchange for no large read at any session start. Whether that trade pays is the brief's *Cost* criterion, measured under one vendor of three. **Four questions are left open in `design/10-design.md` § Open questions** and three of them are the user's rather than the model's: whether the standing corpus outside `design/` (`AGENTS.md` above all, which owns I3, I4, I9 and the marked-region rule) is made of document units; whether the closed class list lives in `20-contract.md` or `AGENTS.md`; and which workflow is the cost baseline, where `/slice` is recommended over `/reconcile` because a benchmark chosen to flatter the change is a reporting failure. **`design/20-contract.md` and `design/30-slices.md` both open by pointing at `10-design.md`'s scope warning for the defect-to-merge path**, which this rewrite replaces; those two pointers are now stale and are `/contract`'s to correct on its next run, not `/design`'s to reach into. **`INSTALL.md` phase 1 names eight `tools/*.ps1` against ten in the tree** - noticed while confirming what ships to targets, left uncorrected because `/design` is not the implementing command that owns descriptive drift.

### 2026-08-12 — `/install-all` gets a mechanically enforced write surface, `tools/Test-WriteSurface.ps1`
Context: Issue #31, sourced from `research/oz-for-oss.md` (§2 F2, §5 P7, Tier 2 port with adaptation). `/install-all` runs many repositories unattended with no per-repo confirmation, and `INSTALL.md`/`install-all.md`'s "what must not happen" lists are instructions, not a check anything actually enforces — a bug or a bad reconciliation call in one target has no mechanical backstop today. Oz's `assert_write_surface` (`oz/repo_local.py`) runs `git diff --name-only base...branch` before push and aborts on any path outside an allowed-prefix list.
Chosen: `tools/Test-WriteSurface.ps1`, structured like `Test-DesignDrift.ps1` (dot-source-testable functions behind an exit-calling wrapper, states not booleans — `InSurface`/`OutOfSurface`/`NotEvaluated`, exit 0/1/2, `NotEvaluated` never reads as a pass). **Adapted from a push gate to an apply gate**: this kit's `/install-all` never commits or pushes at all (`INSTALL.md`, "What installing must not do" — it writes straight to the target's working tree and leaves staging to the user), so there is no push to run the check before. Instead the script reads `git status --porcelain=v1 -uall` in the target and is run once per target immediately after that target's phase-2 writes, before the target is reported done; `-uall` avoids git's own untracked-directory grouping (`?? src/` instead of the file actually written), which would both under-name the offending path and mask an allowed file sitting next to a disallowed one. The allowed-prefix list lives once, in the script (`Get-DefaultAllowedPrefixes`), matching `INSTALL.md` phase 1's artifact table plus `.claude/kit.json`, and deliberately excludes `.claude/settings.json` — `install-all.md` phase 2 always skips that fork unattended, so a write there is a bug the guard should catch, not a case it should allow. `install-all.md` phase 2 now runs it per target and treats exit 1 or 2 as an abort for that target (revert with `-Revert`, report the offending path under a new "Aborted" row in phase 4); phase 3 gained a line naming the guard as the backstop for its existing write-surface rules. `-Revert` uses `git checkout --` for a tracked path and deletion for an untracked one, gated behind the flag rather than run by default (house convention: destructive operations need an explicit flag, never a silent default). Verified against real `git init` repos in `tools/Test-WriteSurface.Tests.ps1`, not mocked git calls: a change confined to the allowed prefixes passes, a change outside them is rejected by name, a mixed change reports only the offending path, a non-git path is `NotEvaluated`, and `-Revert` is checked to actually restore/delete both a tracked and an untracked offender.
Rejected: **Gating a commit or a push**, matching oz literally — no-op here, since neither step exists in this kit's install flow; gating apply is the only point that can actually run. **A read-only report with no `-Revert`** — leaves a target sitting with an unreviewed out-of-surface write in its working tree until someone notices, which is exactly the backstop-less state this guard exists to close; `-Revert` is optional (default off, per house convention) but available so `/install-all` can actually abort a target's pass rather than merely flag it. **Restating the allowed-prefix list in `install-all.md`** — a second copy that rots the moment `INSTALL.md`'s artifact table changes; the script is the one canonical, checkable copy and the command file points at it.
Reversibility: cheap — one new script, one new test file, and a few lines in `install-all.md`'s phase 2–4; none of it changes what `/install-all` is allowed to write, only whether a violation is caught.

### 2026-08-11 — Documents state only what the tree cannot, and descriptive drift is corrected where it is found

### 2026-08-04 — A `SessionEnd` hook writes a cost log, and installs may write that one key

### 2026-08-04 — `Measure-Session.ps1` is Claude Code only, and errors rather than reporting zero
Context: Asked whether the measurement works under Codex and Copilot. It does not, and the way it failed was the problem: pointed at four real Codex transcripts with `-TranscriptPath`, it exited 0 and reported **0 calls, 0 tokens across 4 sessions**. A zero from a measurement tool cannot be told apart from a session that was free, which is the fabricated figure `AGENTS.md` *Verification* exists to prevent. Investigation of the three surfaces: Claude Code (CLI, desktop, and the VS Code extension, which drives the same CLI and writes the same `~/.claude/projects/<slug>/*.jsonl`) works; Codex writes `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` with usage as `token_count` events under `payload.info`; Copilot Chat writes `globalStorage/github.copilot-chat/session-store.db`, whose `turns` table is `(id, session_id, turn_index, user_message, assistant_response, timestamp)` — no usage column anywhere in the schema, because Copilot meters premium requests rather than tokens.
Chosen: Shape-check every transcript before summing it. `Get-TranscriptVendor` classifies by record shape, not by path, so an exported or relocated store is still judged correctly; the two discriminators were verified against every transcript on this machine (18 Claude, 4 Codex): no Claude record carries a top-level `payload`, no Codex record carries a top-level `message.usage`. Anything not `claude` is a hard error naming the vendor. Copilot is named separately by `Assert-NotCopilotStore` because its reason differs in kind — not "unsupported" but "the data does not exist". A directory whose transcripts are all Claude-shaped but all empty errors too; a single empty session among others is still skipped. Scope stated in `AGENTS.md` (*Verification*), `README.md`, and the script's help. Writing the tests surfaced two real bugs in the new code: `$detail` silently assigned to the `-Detail` switch parameter (PowerShell variable names are case-insensitive), and returning early from a `[System.IO.File]::ReadLines` enumerator leaked the file handle, breaking an unrelated test that rewrote the same fixture path.
Rejected: **A Codex reader now** — the mapping is exact and verified (`sum(last_token_usage) == total_token_usage` on both sampled sessions, and `total_tokens == input_tokens + output_tokens`, proving `cached_input_tokens` is a subset of `input_tokens` rather than additive), but `calls` would be per turn against Claude's per call, and `-Detail` has no `<command-name>` markers to segment on. That is a feature with its own units problem, not a bug fix, and it belongs in its own slice. **Narrowing the docs without touching the script** — cheapest, but leaves the silent zero live for any unexpected `-TranscriptPath`, and the zero is wrong for every unrecognised input, not just Codex. **Detecting vendor by path** — wrong exactly where `-TranscriptPath` is most useful.
Reversibility: cheap

### 2026-08-08 — `/pr` absorbs the gate and thread phases; pull requests are never drafts
Context: The slice loop was four commands — `/slice` → `/pr` → `/verify` → `/resolve` — three of which run in the same session, on the same branch, with each one's output written into the previous one's artifact. That is one job invoked four times, and the hand-offs were the only thing the split bought. Separately, a draft pull request splits "opened" from "actually in review": reviewers and the CI gates that ignore drafts see nothing until someone remembers to mark it ready.
Chosen: `/pr` becomes the whole merge-ready pipeline in three ordered phases — description, gates, review threads — and owns the sequence only. `.claude/commands/verify.md` and `.claude/commands/resolve.md` keep sole ownership of their procedures, are run in full by `/pr`, and stay invocable standalone; nothing is copied between the files (*Single ownership*). Phase 3 runs automatically rather than waiting to be asked for: it queries threads immediately, and on an empty result gives the automated reviewers exactly one bounded wait via `tools/Wait-PullRequestCheck.ps1` before re-querying. Drafts are abolished — `/slice`, `/fix`, and `/pr` open a live pull request — and the *Git and delivery* carve-out widens from "opening a draft" to "opening a pull request", on the reversibility argument that closing an open PR is as cheap as closing an issue. Merging stays the user's.
Rejected: **Fold `/track` in too** — it runs after the merge in a fresh session, deliberately, so the session that wrote the code does not get to grade whether the slice is done; merging it would hand doneness to the party with an opinion about it. **Keep `/resolve` separate** — recommended at the time, on the grounds that waiting for review is a different order of wall-clock time from writing a description; overruled by the user, and answered instead by the bounded-wait rule above rather than by a poll loop. **Keep `/slice` and `/fix` opening drafts and have `/pr` ask before marking ready** — preserves the narrower carve-out untouched, but keeps the two-state problem that abolishing drafts exists to remove, and costs a confirmation per slice. **Restate the gate and thread rules inside `/pr`** — would make the command self-contained at the price of two copies of every rule, which this repository's contract forbids for exactly the reason that applies here.
Reversibility: cheap for the command structure; the widened authorization carve-out is a policy change and reverting it means re-adding an ask per pull request.
