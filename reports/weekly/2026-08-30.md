## Findings

1. **Cost is a function of session length, not command choice.** Cache read is 98.13% of
   input-side volume, and it grows with conversation length. The heaviest sessions chain
   `/slice` → `/pr` → `/clean` in one window (e.g. session `61942d83` in GameEngine: 651
   calls, 365,070 tokens/call average).
2. **A third of the week was housekeeping-only.** 219 of 324 sessions contained none of
   `/slice`, `/fix`, `/design`, `/contract`, `/pr`, `/code-review` — 1,556,315,047 cache
   read (32.5% of the week) for tracker syncs, branch cleanup, and orientation.
3. **`/clean` ran 134 times, 19 sessions ran it more than once.** 42 of those runs were
   repeats inside a session that had already run it, costing 98,041,183 tokens for a
   second no-op.
4. **The `SessionEnd` cost-log hook captured 52% of sessions this week** (170/324).
   `Data.Json`, `ServiceContract` and `SunTrap` have activity but no
   `.claude/session-costs.tsv` at all.
5. **`Measure-Session.ps1` does not see subagent transcripts.** It lists `*.jsonl`
   non-recursively in the project directory; subagent transcripts sit under
   `<session>/subagents/`. Every figure this tool reports is understated — 6.1% overall,
   20% in AgentKit specifically (151,327,897 of 761,589,768 unseen).
6. **Sunday was 48% of the week** — 119 sessions, 12,958 calls, 30.5 active hours.
   Friday had none.
7. **`SubZeroDev.Git` and `SubZeroDev.GitService` are duplicate checkouts** of the same
   remote at the same commit — double-counted in any per-folder measurement.
8. **`SubZeroDev.SunTrap` has the `SessionEnd` cost hook but not the `-Watch` context
   hook** — install drift versus every other active repository.
9. **Model routing is broadly holding**: 73% Sonnet-only sessions, 16% Opus-only, 9%
   mixed within a session. Deep-reasoning commands (`/design`, `/contract`, `/slices`,
   `/reconcile`) totalled 31 runs.
10. **Worktrees carried 2% of the week's volume** (6 of 324 sessions) — under-used given
    the "one slice per session" rule and several repositories moving in parallel.

## Recommendations, ranked by measured return

1. **Make `/clean`, `/done` and `/next` scripts, not sessions.**
   `tools/Invoke-DoneHousekeeping.ps1` already implements the branch-safety check these
   commands need — the remaining work is calling it from a shell alias instead of a
   model. Recovers ~482M cache read/week (findings 2, 3).
2. **Give the 150k `-Watch` warning teeth.** It fires and nothing changes; 70 sessions
   ran past it for 69% of the week's volume (finding 6/session-size). Either raise the
   threshold to one that will be acted on, or make the message name the session-boundary
   action directly.
3. **Teach `Measure-Session.ps1` to recurse into `<session>/subagents/`**, reported as a
   separate line rather than folded into the parent session's total (finding 5).
4. **Diagnose the `SessionEnd` capture gap and backfill the missing rows** — transcripts
   are durable, so this is a re-measurement pass, not lost data (finding 4).
5. **Stop chaining `/clean`/`/track` onto the end of a `/slice` → `/pr` session** — the
   contract already requires `/slice` and `/pr` to share a session; the trailing
   housekeeping doesn't need that session's context (finding 1).
6. **Resolve the duplicate `Git`/`GitService` checkout and add the missing `-Watch` hook
   to `SunTrap`** (findings 7, 8) — both cheap, both currently silently wrong.
7. **Use worktrees for slices expected to run long**, to unblock other work on the same
   repository in the meantime (finding 10).

*No prices are applied in this report, matching `tools/Measure-Session.ps1`'s own
policy (`design/cost.md`): a rate applied from memory is the fabricated number the tool
exists to replace.*
